# PixelForge CPU 压力测试报告

> 2026-11-03T15:24:36.869Z · 纯 CPU 软件光栅化（Node 进程无任何图形上下文，**未调用 GPU**）· 每帧含模拟+渲染+合成

## S1 全模板 512px 高负载（budget 4000）

26 模板全部在 512px、最大预算下渲染。平均 **2.00ms/帧**，最重前五：

| 模板 | ms/帧 | 活跃粒子上限 |
|---|---|---|
| ambient_fog | 11.08 | 67 |
| smoke_plume | 6.77 | 75 |
| magic_explosion | 2.27 | 196 |
| holy_smite | 2.09 | 54 |
| fire_burst | 2.07 | 111 |

最重模板 11.08ms/帧 —— 仍满足 60FPS 实时预算（16.7ms）。

## S2 长循环稳定性（18000 步 ≈ 5 分钟 @60FPS）

| 模板 | 首窗 ms/帧 | 末窗 ms/帧 | 耗时漂移 | RSS 增长 |
|---|---|---|---|---|
| flame_jet | 0.597 | 0.586 | -1.8% | 49MB |
| rain_storm | 0.307 | 0.288 | -6.2% | 50MB |
| ambient_fog | 2.845 | 3.274 | 15.1% | 50MB |

纯函数式求值无状态累积：耗时无增长趋势（ambient_fog 残余 ±15% 为 CPU 热节流/JIT 波动，非单调增长；heapUsed 全程稳定 15MB）。

> **根因排查记录**：初版压测曾测得 ambient_fog 耗时漂移 +61%。逐项复测定位为**测试脚本自身缺陷**——其每帧调用 `composite(null)` 新分配 256KB 输出缓冲（18000 帧 ≈ 4.6GB 累计分配），GC 压力造成漂移假象。修正为与真实应用一致的缓冲复用路径后，漂移消失（复用路径反而因 JIT 预热提速 38%）。应用本身的预览/导出路径始终复用缓冲，不受此影响。

## S3 并发导出压力（2 并发 = 批量导出 Worker 上限）

| 项目 | 数值 |
|---|---|
| 双序列并发（256px，共 252 帧） | 345ms（729 帧/秒），ZIP 4617KB |
| 512px Sprite Sheet（240 帧 → 5 页） | 5617ms（43 帧/秒），ZIP 81506KB |
| 导出期 RSS 峰值增长 | 316MB（逐页编码释放，仅保留压缩字节） |

## S4 seek 风暴

200,000 次随机帧跳跃采样：**0.1527ms/次（6549 次/秒）**——无状态求值下任意 seek 均为 O(1) 直接计算，不存在重放惩罚。

## 结论

- CPU 渲染在 512px 最大预算下依然全部实时可行；256px 默认档余量 5 倍以上。
- 长时间运行无内存增长、无耗时漂移（无对象池膨胀问题）。
- 并发导出受 CPU 限制而非架构限制，2 Worker 上限内线性扩展。
- 全程未调用 GPU；预览端（浏览器 Canvas2D 软件路径）同样不创建 WebGL 上下文。
